# inf-20100313 (Infdev 20100313)

Support added after inf-20100227-1433. Protocol number 12. SHA-256 of the original jar:
`4974d31eb0af16ddbaaa2d81e88943baeaf8bbc0106a8db20cda19f4a824152d`.

## What the build changes (from the jar, and the wiki page)

- World class renamed `net/minecraft/a/a/e` -> `net/minecraft/a/a/f`; the world is no longer 256x256x256 + a chunk
  store: chunks are `net/minecraft/a/a/e/d` objects handed out by a chunk provider (`net/minecraft/a/a/e/a`,
  field `q` of the world). The provider is a 32 x 32 ring buffer (`e/b`) in front of the terrain generator (`e/e`):
  a chunk that falls out of the ring is generated again, nothing is saved.
- Chunk: block array `a`, metadata `c`, sky light `d`, block light `e` (nibble arrays `e/c`, field `a`), height
  map `f` (index z * 16 + x), lowest height `g`, chunk numbers `h`, `i`. Public constructor
  `(world, byte[] blocks, int cx, int cz)`; `b()` recalculates the sky light.
- Chunks are found with an unsigned shift (`x >>> 4`): negative coordinates are huge positive chunk numbers.
- World: `a(III)` block id, `b(IIII)Z` set block (also updates the light), `c(III)` metadata, `a(IIII)V` set
  metadata, `d(III)` light, field `j` time in ticks (a day is 12000 ticks), `a(IIIIII)` marks a region for redraw.
- Light: working sky and block light, dynamic light updates; the obsidian wall structure is gone; new worlds
  start with 999 of several blocks; the day and night cycle is back.

## Server (`server/bridge313/TWBridge313.java`)

The bridge replaces the game's chunk provider (java.lang.reflect.Proxy over the game's own interface) with one that
keeps the chunks, reads them from `worlds/inf-20100313/<level>/c.X.Z.dat` (GZIP NBT, tags of 20100630: Blocks,
Data, SkyLight, BlockLight, HeightMap) or asks the game's generator, and drops chunks far from all players. Time
advances once per server tick and is sent to the clients now and then. The player spawns where a single player
does (0, 64, 0 moved out of blocks, then onto the ground or water surface). No mobs, items or tile entities.

## Client (`client/mod313/TW313Client.java`)

Same hooks as 20100227 (see `ClientPatcher.createTransformer313`) except: the set-block hook is on `f.b(IIII)Z`,
there is a set-metadata hook on `f.a(IIII)V`, and there is no terrain hook: the client replaces the world's chunk
provider by one that serves only the chunks received from the server (blocks, metadata, sky light, block light,
height map). The world time (field `j`) is set from the login and time packets.

## Other players on the client (found by testing)

- The renderer of this build draws the world relative to the camera: the modelview matrix at the entity pass has the camera's rotation only, but `RenderManager.a(entity, partial)` passes absolute world coordinates to the entity renderers. The mod therefore translates by minus the manager's camera position (fields f, g, h) around the player drawing; without it the players were drawn 80 blocks above the camera (invisible, hits still worked). The name tag is projected from the vector from the camera with the same rotation-only matrix.
- The render manager's texture field (`b`) is empty by the end of the entity pass and this build draws entity shadows with it (NullPointerException every frame): the mod calls `RenderManager.a(world, textures, player, partial)` again before drawing the players.

## Plugin API

The build has its own plugin API (`api/inf-20100313/`, `net.thewellodev.api313`): the API of 20100227 plus block data (metadata)
and the world time (a day is 12000 ticks in this build). The server view is in `server/src/.../api313`, the plugins in
`plugins/inf-20100313/`. See [../plugin-api/inf-20100313.md](../plugin-api/inf-20100313.md).
